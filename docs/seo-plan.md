# SEO-план OSNOVA (черновик)

Статус: черновик до сбора реального семантического ядра (частот, кластеров).
Цель документа — зафиксировать структуру страниц, их поисковые интенты и правила,
исключающие каннибализацию. Реальные ключевые слова и частоты заполняются
отдельно, после сбора семантики.

## Принципы

1. Одна страница = один поисковый интент. Две страницы с одинаковым интентом
   конкурируют друг с другом и размывают ссылочный вес.
2. Каталог и хабы не дублируют друг друга: каталог транзакционный («решить»),
   хабы — обзорные («что разбираем, с чего начать»).
3. Каноникализация: все фильтры каталога → `/zadachi`; фильтры не создают
   отдельных URL в sitemap.
4. `lastModified` в sitemap — реальные даты публикации/обновления, не дата сборки.

## Семантические кластеры

| Кластер | Интент | Страницы |
| --- | --- | --- |
| Банк задач | «решить задачу по …» | `/zadachi`, `/zadachi/[id]` |
| Предмет | «математика/информатика ОГЭ ЕГЭ — что нужно» | `/matematika`, `/informatika` |
| Разборы/статьи | «как решать тему X», «разбор ошибки» | `/articles`, `/articles/[slug]` |
| Подготовка к экзамену | «как готовиться к ЕГЭ/ОГЭ по предмету» | `/ege-…`, `/oge-…` (P1) |
| Услуга | «репетитор/занятия» | `/podgotovka` |
| Лид-магнит | «проверить уровень» | `/diagnostika` |
| Юридическая | доверие/обязательное | `/privacy` |

| Маршрут | Интент | Статус |
| --- | --- | --- |
| `/` | бренд + вход в каталог/услугу | есть |
| `/zadachi` | каталог задач (фильтры) | есть |
| `/zadachi/[id]` | конкретная задача + решение | есть |
| `/articles` | список разборов | есть |
| `/articles/[slug]` | статья-разбор | есть |
| `/matematika` | хаб: предмет, темы, задачи, статьи | есть |
| `/informatika` | хаб: предмет, темы, задачи, статьи | есть |
| `/podgotovka` | услуга + форма заявки | есть |
| `/diagnostika` | бесплатная диагностика | есть |

## Список страниц P1 (рост)

| Маршрут | Интент | Отличие от существующих |
| --- | --- | --- |
| `/ege-matematika` | гайд «как готовиться к ЕГЭ по математике» | от `/matematika` (обзор предмета) и `/zadachi` (решить) |
| `/oge-matematika` | гайд ОГЭ по математике | аналогично |
| `/ege-informatika` | гайд ЕГЭ по информатике | аналогично |
| `/oge-informatika` | гайд ОГЭ по информатике | аналогично |
| `/zadachi` с параметром `topic` (P2) | «задачи по производной» и т.п. | только после реального банка тем |

Не создавать (дубли): `/zadachi/matematika`, `/zadachi/informatika` — уже
покрыто query-фильтром с canonical на `/zadachi`; отдельные страницы на каждый
`topic` без уникального контента.

## Правила против каннибализации

- `/matematika` и `/zadachi?subject=matematika`:
  - хаб — человеческий обзор (темы, «что разбираем», избранные задачи, статьи);
  - каталог — список задач с фильтрами.
  - Разные H1/description, перелинковка хаб↔каталог.
- Экзаменационные гайды (`/ege-…`) отличаются по цели («как готовиться»), а не
  по «списку задач», и не должны дублировать тексты хаба.

## Конвенции

- `buildMetadata()` задаёт title/description/canonical/OG/robots для каждой страницы.
- Sitemap: статические маршруты + задачи/статьи из API (`getTaskIds`/`getArticles`).
- Черновики: `noIndex` через `buildMetadata({ noIndex: true })`; опубликованный
  контент помечается `is_published`.

## Дальнейшие шаги

1. Собрать семантическое ядро (частоты, кластеры) и заполнить таблицы ключей.
2. Прописать title/description/H1 под каждый кластер.
3. Перелинковка задач↔статей по темам после расширения банка.
