# План и отчёт миграции

Исходник — единственный файл `../ideal.html` (796 строк: инлайн-CSS, разметка и
скрипт, ~270 строк JS, KaTeX с CDN). Он сохранён в репозитории как дизайн-
референс; в первом коммите зафиксирована его исходная версия.

## 1. Результат аудита

### Что было

- Одностраничный сайт репетитора с 8 секциями внутри `<main>`, шапкой и
  подвалом.
- Дизайн-система в CSS-переменных: цвет, типографика, радиусы, easing,
  три брейкпоинта (1400+/1199/767 px).
- Своя 12-колоночная сетка `.grid`, контейнер 1440 px, крупная типографика
  (`clamp`), шрифты Geist + Instrument Serif, акцент `#3157D5`.
- Интерактив:
  - анимация появления hero-формул по частям и отрисовка графика производной
    (`stroke-dashoffset`), параллакс по скроллу;
  - викторина «Проверьте себя» с проверкой ответа, подсказками для каждого
    неверного варианта и пошаговым решением;
  - демонстрация задачи по информатике: набор Python-кода по символам,
    прогон цикла с логом и выводом результата;
  - анимация SVG-иллюстрации в секции «Подход» по попаданию во вьюпорт;
  - «шторка» мобильного меню;
  - математика через KaTeX (CDN, рендер по `data-tex`).
- `prefers-reduced-motion` обрабатывался.
- 9 ссылок-заглушек `href="#"`.
- Заглушки в контенте: `Имя Фамилия` в шапке и подвале, `@username (добавить)`
  в контактах, пустой `og:image`.

### Проблемы, найденные при аудите

1. **Девять нерабочих CTA.** Все карточки статей, все карточки задач и четыре
   кнопки вели в `#`.
2. **Фиктивная личность и контакты** в публичном интерфейсе.
3. **Пустой `og:image`** — метатег присутствовал со значением `""`.
4. **Внешний CDN для формул**: KaTeX грузился с `cdn.jsdelivr.net`, формулы
   появлялись только после клиентского скрипта → их не было в HTML.
5. **Весь контент зависел от JS**: класс `.reveal` (opacity: 0) снимался
   скриптом; без JavaScript страница оставалась пустой.
6. **Математика в тексте решений** (шаги викторины) подставлялась через
   `innerHTML` в обработчике клика.
7. **Доступность**: скрытая ссылка «Перейти к содержимому» никогда не
   показывалась; мобильное меню без ARIA-контракта и фокуса; рейтинг сложности
   передавался только цветом баров.
8. **Дублирование разметки**: JS вручную строил сетку графика и подсвечивал код.
9. **Нет SEO-инфраструктуры**: robots, sitemap, canonical, JSON-LD, отдельных
   страниц задач и статей.

## 3. Что изменено и почему

### Исправлено (было сломано или вводило в заблуждение)

- **Убраны все `href="#"`** (9 штук). Каждая карточка и CTA ведут на реальный
  маршрут; ни одна кнопка не является заглушкой.
- **Удалены вымышленные личность и контакты.** Бренд, Telegram и e-mail берутся
  из окружения. Пока они не заданы:
  - бренд — «Математика · Информатика»;
  - в подвале вместо контактов ссылка «Связаться по занятиям»;
  - форма заявки заменена честным сообщением о том, что приём заявок не
    настроен (вместо кнопки, имитирующей отправку).
- **`og:image` больше не выводится**, пока нет реального изображения 1200×630.
- **Формулы теперь в HTML.** KaTeX вызывается на сервере, CDN не используется.
- **Контент виден без JavaScript.** Скрытие через `.reveal` включается только
  при включённых скриптах (CSS-медиафункция `scripting`); для интерактивных
  блоков есть статичные варианты (`.no-js-only`).
- **Доступность:** ссылка «Перейти к содержимому» показывается при фокусе;
  `aria-expanded` у элементов раскрытия; `aria-live` для результатов викторины и
  проверки ответа; текстовое название сложности рядом с барами; SVG-график
  получил `role="img"` и `aria-label`, а подпись стала `figcaption`.

### Сохранено намеренно

- Визуальная концепция, цвета, типографика, сетка, отступы, радиусы и
  `easing` перенесены как токены Tailwind 4 без редизайна.
- Порядок секций главной страницы не менялся (проверяется e2e-тестом на наличие
  всех заголовков).
- Параллакс hero, пошаговое появление формул, отрисовка графика, анимация
  иллюстрации, набор кода и прогон цикла — сохранены.
- `prefers-reduced-motion` поддержан и расширен: анимации отключаются, финальное
  состояние показывается сразу.

### Осознанные отклонения от исходника

1. **Порядок статей** на главной сохранён таким же, как в прототипе (ведущая —
   про производную). Сортировка по дате не применяется: порядок curated, и его
   будет определять API.
2. **Боковой список статей на планшете** (768–1199 px) в прототипе
   перестраивался в строку; в миграции он остаётся колонкой с разделителями —
   поведение одинаково и предсказуемо на всех ширинах.
3. **Кастомный брейкпоинт** `desk` равен 1200 px и выражен в `rem` (`75rem`).
   В `px` Tailwind сортировал медиазапросы неверно, и desktop-правила
   проигрывали `sm`/`md` — это было найдено и исправлено при проверке.
4. **Демонстрационные данные помечены.** Шесть задач и три статьи — новый
   контент, написанный для миграции. Все ответы проверены вручную, статьи
   содержат только проверяемые объяснения (без отзывов, результатов учеников и
   прочих неподтверждённых фактов) и явно помечены в интерфейсе как
   демонстрационные/черновые.
5. **Статья №5 из прототипа** (набор кода) вынесена в переиспользуемый модуль
   `features/home/lib/task5.ts` и покрыта тестами: он же используется
   анимацией, поэтому поведение и эталонный ответ теперь проверяемы.

### Дефекты, найденные и исправленные при проверке

Ниже — не «долги», а уже исправленные проблемы, которые не видны в собранном
результате, но важны для контекста:

1. **Hydration mismatch на `<html>`.** Первая версия прогрессивного улучшения
   добавляла класс `js` на `<html>` инлайн-скриптом. Скрипт менял атрибут
   `class`, которым управляет React, и гидратация сообщала о несовпадении.
   Механизм переписан на CSS-медиафункцию `scripting` — мутации DOM больше нет,
   инлайн-скрипт удалён. Дополнительно на `<html>` и `<body>` добавлен
   `suppressHydrationWarning` — для атрибутов, которые дописывают браузерные
   расширения (LanguageTool, Grammarly).
2. **Дублирующиеся React-ключи** в анимации демо-кода: две одинаковые строки
   `s += str(s.count('1') % 2)` давали одинаковые `key`. Исправлено на индекс
   строки (список фиксированный и не переупорядочивается).
3. **Секции главной оставались невидимыми.** `ScrollReveal` живёт в `layout`,
   который при client-side навигации не перемонтируется, поэтому эффект не
   перезапускался: наблюдатель следил за узлами предыдущей страницы, а новые
   `.reveal` навсегда оставались `opacity: 0`. Плюс `IntersectionObserver`
   пропускал элементы при быстрой прокрутке и прыжке в конец. Эффект теперь
   зависит от `usePathname()`, а показ выполняется детерминированной проверкой
   по `scroll`/`resize`. Закреплено e2e-тестами на прыжок в конец и на
   soft-навигацию.
4. **Порядок медиазапросов** из-за брейкпоинта `desk` в `px` (см. отклонение 3).
5. **Мягкий 404** при включённых Cache Components (см. `architecture.md`, §7).
6. **Автозапуск анимации Python-кода не срабатывал.** `CodeDemo` ставил
   `startedRef = true` при первом `useEffect` и не пересоздавал
   `IntersectionObserver`. В dev-режиме React StrictMode монтирует эффект
   дважды, поэтому после второго монтирования наблюдатель был уничтожен, и
   демонстрация запускалась только по кнопке «Показать ещё раз». Защита
   `startedRef` убрана — наблюдатель корректно пересоздаётся при каждом
   монтировании.
7. **SVG-иллюстрация «Подход» рисовалась пунктиром.** При переносе из прототипа
   у `.draw`-фигур потерялся атрибут `pathLength="1"`. Без него
   `stroke-dasharray: 1` — это штрих 1px/1px, а не «один штрих на весь путь», и
   анимация сдвигала пунктир вместо отрисовки линии. Атрибут возвращён.
