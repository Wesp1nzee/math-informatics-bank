# Что дальше

Документ фиксирует, что **ещё не сделано**, и какими шагами подключается
Python-бэкенд. Ничего из перечисленного ниже в репозитории не реализовано —
чтобы не создавать видимость готовой функциональности.

## 1. Перед публикацией (обязательно)

1. **Заполнить данные преподавателя.** В `.env.local`:
   - `NEXT_PUBLIC_SITE_URL` — реальный домен (от него зависят canonical и
     sitemap);
   - `NEXT_PUBLIC_TUTOR_NAME` — имя для бренда;
   - `NEXT_PUBLIC_TUTOR_TELEGRAM` и/или `NEXT_PUBLIC_TUTOR_EMAIL` — контакты.
     Пока этого нет, форма заявки на `/podgotovka` скрыта, а бренд остаётся
     нейтральным. Проверить: запустить `pnpm build && pnpm start` и убедиться, что
     в шапке и подвале появились реальные данные.
2. **Добавить изображение Open Graph** 1200×630 в `public/og/` и передать путь в
   `buildMetadata({ ogImage: "/og/....png" })`. Сейчас `og:image` не выводится
   вообще — это лучше пустого значения.
3. **Заменить демонстрационный контент.** Шесть задач
   (`src/features/tasks/fixtures/tasks.ts`) и три статьи
   (`src/features/articles/fixtures/articles.ts`) — это наполнение для
   разработки. Либо перенести их в CMS/БД, либо расширить вручную.
4. **Проверить юридические тексты.** Если заявки будут собираться через
   сервер — нужна страница политики обработки персональных данных и ссылка на
   неё из формы (сейчас чекбокс согласия ссылки не содержит).
5. **Добавить favicon и apple-touch-icon.** В проекте есть `src/app/icon.svg`
   (абстрактный знак), но нет отдельного `apple-icon`/manifest.
6. **Настроить заголовки безопасности** для продакшена (`Content-Security-Policy`,
   `Strict-Transport-Security`, `Referrer-Policy`) в `next.config.ts` или на
   уровне хостинга.

## 2. Подключение FastAPI

Порядок действий, при котором фронтенд почти не меняется:

1. **Зафиксировать контракт.** Реализовать в FastAPI эндпоинты, ожидаемые
   фронтендом:
   - `GET /tasks` → `{ items: Task[], total: number, page: number, page_size: number }`
     с query-параметрами `subject`, `level`, `page`, `page_size`, `featured`;
   - `GET /tasks/{id}` → `Task` или 404;
   - `GET /tasks/{id}/related?limit=` → `{ items: Task[] }`;
   - `GET /articles` → `Article[]`;
   - `GET /articles/{slug}` → `Article` или 404;
   - `POST /tutor-leads` ← `TutorLeadInput`
     (`{ name, contact, subject, message?, consent: true }`).
     Поля должны совпадать с `src/features/tasks/types.ts`,
     `src/features/articles/types.ts` и `src/features/tutor-leads/types.ts`.
2. **Сгенерировать типы из OpenAPI**, чтобы не поддерживать два источника истины:
   ```bash
   curl http://localhost:8000/openapi.json -o openapi.json
   pnpm dlx openapi-typescript ./openapi.json \
     -o src/lib/api/generated/schema.d.ts
   ```
   Затем заменить DTO внутри `features/<feature>/api.ts` на сгенерированные типы
   с явным маппингом на доменные. Каталог `src/lib/api/generated/` для этого уже
   подготовлен.
3. **Задать адреса API.** В `.env.local`:
   ```bash
   # серверные запросы (SSR/сборка) — может быть внутренний адрес
   API_BASE_URL=http://localhost:8000
   # браузерные запросы (POST заявки)
   NEXT_PUBLIC_API_BASE_URL=http://localhost:8000
   ```
   Каталог и страницы автоматически переключатся с фикстур на API
   (`isServerApiConfigured()` в `features/tasks/api.ts` и
   `features/articles/api.ts`). Ничего больше менять не нужно.
4. **Настроить CORS на бэкенде.** Так как браузер обращается к API напрямую
   (`POST /tutor-leads`), разрешить origin фронтенда:
   ```python
   from fastapi.middleware.cors import CORSMiddleware
   app.add_middleware(
       CORSMiddleware,
       allow_origins=["http://localhost:3000", "https://<домен>"],
       allow_methods=["GET", "POST"],
       allow_headers=["Content-Type", "Accept"],
   )
   ```
   Если заявки пойдут через серверный прокси Next.js, CORS для браузера не
   потребуется — но прокси стоит добавлять только при конкретной задаче
   (например, работа с cookie и серверными секретами). Сейчас прокси нет
   намеренно.
5. **Включить кеширование.** `serverRequest` уже принимает `tags`; добавить
   теги к запросам и вызывать `revalidateTag` из вебхука/админки после правок
   контента. До этого страницы остаются статическими.
6. **Big-bank: перейти на `dynamicParams = true`.** Сейчас задачи и статьи
   предгенерируются из известных id/slug (`generateStaticParams`), а неизвестные
   дают корректный 404. Когда банк станет большим, разумно рендерить страницы
   задач по требованию с ISR.

### Локальный запуск фронтенда вместе с API

```bash
# терминал 1 — бэкенд
uvicorn app.main:app --reload --port 8000

# терминал 2 — фронтенд
cd frontend
cp .env.example .env.local   # прописать API_BASE_URL и NEXT_PUBLIC_API_BASE_URL
pnpm dev
```

Проверить, что фронтенд действительно ушёл в API: временно остановить бэкенд —
каталог должен показать состояние ошибки из `StateMessage`, а не фикстуры.

## 3. Следующий этап продукта

1. **Поиск по банку задач.** Сейчас есть только фильтры по предмету и
   сложности. Дальше — поиск по тексту условия (серверный, индексируемый) и
   страница результатов. Каталог `features/search/` не создан специально: он
   появится вместе с реальной задачей. Предпочтительно SSR + `searchParams`,
   как у фильтров, чтобы ссылки были шарящимися и индексируемыми.
2. **Тренажёр и прогресс.** Для тренировки с клиентской проверкой ответов и
   сохранением прогресса появится смысл в `@tanstack/react-query` (клиентский
   кэш серверных данных, оптимистичные обновления) и в личном кабинете.
   Тогда же имеет смысл ввести группу маршрутов `(app)` рядом с `(public)` и
   авторизацию.
3. **Онлайн-школа.** Расписание, домашние задания, разборы — потребуют
   доменных фич (`features/schedule`, `features/assignments`) и, вероятно,
   генерации типов из OpenAPI для каждого ресурса.
4. **Аналитика и A/B.** Пока не подключено ничего; при добавлении важно не
   ломать LCP на публичных страницах и не добавлять сторонние скрипты в
   критический путь.
5. **Контентные улучшения SEO.** После появления реального банка: страницы
   подборок («Задачи ЕГЭ по производной», «Системы счисления: разборы»),
   перелинковка между задачами и статьями, расширенные тексты описаний.

## 4. Известные ограничения текущей реализации

- Демонстрационные задачи и статьи помечены в интерфейсе как тестовые; это
  честное состояние, но не продакшн-контент.
- Плитки задач и статей на главной ведут на реальные страницы, однако
  «показать ещё» внутри каталога отсутствует — есть пагинация по 4 задачи.
- Форма заявки при отсутствии API открывает Telegram/e-mail клиент
  пользователя с готовым сообщением; явной серверной доставки заявок пока нет.
- Изображения Open Graph не заданы (нет самого изображения).
- E2E-тесты запускаются локально против production-сборки; CI-конфигурация в
  репозитории не добавлена.
